Head content belongs solely in the credential-free sandbox. Policy, independent

## Result-writer compatibility

Reserve exactly `agent-board-review-result-v1` for the independently checked
review writer, conditional on `kind=review`. The consumer requires exactly one
successful completed job of that name in the latest attempt (one page, at most
100 jobs). It must belong to the recorded run and contain the review submission
time within its start/end interval. The successful completed default-branch
dispatch run must match the configured workflow, repository and exact head run
title, and follow the bot-authored durable reservation. Verify the actual jobs
API name after reusable-workflow composition; a source job key alone is not proof.

Only that writer may submit the Actions-bot `APPROVED` review at the inspected
head, carrying one `agent-board-draft-review` JSON fence and the single gh-aw run
marker. It must publish independently checked evidence, not raw sandbox output.
The `agent-board/draft-review/v1` object binds repository, PR, reviewed head,
exact title and description, semantic diff assessment, description assessment,
change category, risk, evidence and reason. Unknown fields/versions, duplicate
fences and stale bindings are invalid. Evidence/reason are nonempty single lines
of at most 1024 bytes each; the whole review is at most 8192 bytes.

Unknown/unsupported assessment remains deep. Quick needs semantic `pass`,
description `matches`, risk `none`, a supported category and no architecture
findings, plus the consumer's deterministic vetoes. The consumer bounds quick
to five files and 150 added/deleted lines, with complete textual diffs, known
paths/statuses and both names of renames checked. Paths alone never attest
semantics. CI needs a nonempty complete current-head inventory, SUCCESS rollup
and no missing, pending or failed required checks, including classic protection
and rulesets (at most five pages of 100 checks). Incomplete/unknown data is deep,
not permission to skip a check or start fix work.
