# Booted tests

These are intended to run via tmt.

## Composefs EROFS V1/V2 regression coverage

The existing `BOOTC_erofs_version` configuration selects the format while the
image is built and is forwarded to tmt by `just test-tmt-nobuild`. It is not
an install flag: installation consumes the UKI already present in the image.
Use the same control for the base and synthetic upgrade images:

```console
export BOOTC_variant=composefs BOOTC_bootloader=systemd
export BOOTC_boot_type=uki BOOTC_seal_state=sealed
BOOTC_erofs_version=v1 just test-tmt readonly image-upgrade-reboot
BOOTC_erofs_version=v2 just test-tmt readonly image-upgrade-reboot
```

`readonly/046-test-erofs-version.nu` checks the booted root identity. Its V1
assertion requires the V2 fallback argument, and explicit V2 requires only the
legacy argument. This is a format regression check, not an old-client bridge
test. `image-upgrade-reboot` builds its derived UKI with the same selected
format and verifies current-client-to-current-client upgrade behavior. The
default `v1` case is dual-format (V1 then V2); it is not an initramfs
capability probe.

`composefs-1-16-bridge` is historical-client coverage: a system installed by
a pinned bootc 1.16 release (the stager) switches to the current image with
that old client, then upgrades and rolls back with current bootc. It is
disabled by default in the plan (enabled by `--context composefs_bridge=true`).
It requires a read-only shared container store and prebuilt fixture images;
the test itself does not build, copy, or SCP images.
`just test-composefs-bridge MODE [STAGER]` builds the fixtures from the
current tree and runs it; CI does this on Fedora 44. The stager is the current
image with bootc replaced by the pinned RPM and its initramfs (and UKI)
regenerated by that version (`tmt/tests/Dockerfile.composefs-1-16-stager`).

Two stagers are pinned, because the old client's behavior changed within
1.16:

- 1.16.0 (like 1.16.1 and 1.16.2) generates V2 EROFS images and reads only
  the bare `composefs=` argument, so it stages the V2 fallback of the
  dual-digest UKI;
- 1.16.4 generates V1 (composefs-rs 080f925) and reads `composefs.digest=`
  first, so on a repository it created it stages V1 directly.

1.16.3 is not covered: it already reads `composefs.digest=` but still
generates V2, so switching to a dual-format UKI fails with "The UKI has the
wrong composefs= parameter". Neither is 1.16.4-1.16.14 staging a UKI on a
system installed by 1.16.0-1.16.3: such a repository reads as V2 (explicitly
recorded by 1.16.3, absent before) and is never converted, so it fails the
same way (bootc-dev/bootc#2334). The 1.16.4 stager avoids this by installing the
system itself.

MODE is `sealed` (UKI, ext4, Secure Boot firmware), `unsealed` (UKI, xfs,
missing fs-verity allowed, insecure firmware) or `bls` (grub, ext4). On BLS the
old client writes the boot entry for the current image itself, with only a
bare `composefs=` argument. CI runs 1.16.0 sealed and unsealed, 1.16.4 sealed,
and 1.16.4 BLS.

The recipe passes the fixture details as environment variables:
`BOOTC_bridge_mode`, `BOOTC_bridge_stager_version`,
`BOOTC_bridge_stager_format` (the format the stager stages: `v2` for 1.16.0,
`v1` for 1.16.4) and `BOOTC_bridge_stager_bootc_sha256`, the checksum of the
pinned `/usr/bin/bootc`, which the test verifies (and records with the exact
`bootc --version` and RPM NEVRA) before staging anything. The images are
labeled `bootc.test.fixture=bootc-STAGER-stager`, `current-MODE` and
`current-MODE-upgrade`, and the test refuses mismatched fixtures.

After each boot the test checks the booted image in bootc status, the root
mount source, `missingVerityAllowed` against the mode, and that the
repository image and deployment state exist. It reads the EROFS format of
the booted image from the `composefs_version` field of its composefs header
and expects the stager's format after the switch and after the rollback,
and V1 after the upgrade. On UKIs it also checks the dual-format arguments,
including the `?` marker in the unsealed case; on BLS, that the booted digest
is on the kernel command line. `/etc` and `/var` sentinels must survive
throughout. Rollback and `composefs-gc --assert-no-op` run only with current
bootc; no old 1.16 rollback or GC command is assumed.

This intentionally does not cover stale initramfs or old-initramfs-mode. The
test is disabled by default in the plan, so the regular test-integration
matrix doesn't build these large fixtures; CI runs it in its own job.
